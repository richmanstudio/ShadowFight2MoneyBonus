# Для любознательных: как проверяется сохранение Shadow Fight 2

> **Если ты просто хочешь изменить монеты, этот документ не нужен.** Открой [пошаговую инструкцию для игроков](START_HERE.md). Программа сама выполняет эту проверку.

[← README](../README.md)

## Формула

```text
N = нормализованный XML
A = UPPERCASE_HEX(MD5(UTF8(N)))
S = device_value + "com.nekki.shadowfight" + suffix
H = UPPERCASE_HEX(MD5(UTF8(A + S)))
```

Постоянный суффикс:

```text
wqO+Qchj|r*QXg7o_KNmLYvpGHdSwqxwlQI2vy618KaD^Pwt-h3H8*uJ
```

`H` записывается в `.hash` как **32 ASCII-символа в верхнем регистре**, без BOM, перевода строки, кавычек и бинарного MD5-дайджеста.

Хешируется весь XML. Одних `Money` и `Bonus` для воспроизведения недостаточно: важны все остальные данные, сериализация, соль и кодировка. Обычный `MD5(raw_file)` не заменяет эту процедуру.

## Минимальный код

```python
from hashlib import md5

SUFFIX = "wqO+Qchj|r*QXg7o_KNmLYvpGHdSwqxwlQI2vy618KaD^Pwt-h3H8*uJ"

def md5_upper(value: bytes) -> str:
    return md5(value).hexdigest().upper()

def calculate(xml_bytes: bytes, device_value: str) -> bytes:
    text = xml_bytes.decode("utf-8-sig")
    normalized = "".join(line.strip() for line in text.splitlines())
    first = md5_upper(normalized.encode("utf-8"))
    salt = device_value + "com.nekki.shadowfight" + SUFFIX
    return md5_upper((first + salt).encode("utf-8")).encode("ascii")
```

Это ядро расчёта, а не самостоятельная безопасная процедура редактирования. Перед применением обязательно сравните результат с **исходным** `.hash` своего нетронутого экспорта. Полная реализация с проверками: [sf2save.py](../sf2save.py).

## Значение для соли

В проверенном iOS-экспорте подходящая UUID-часть находилась в строке вида:

```text
sf2;Android;<UUID>
```

в `Container/Library/Preferences/com.nekki.shadowfight.plist`, в том числе в `user_id`. В соль входила только UUID-часть, с исходным регистром, **без `sf2;Android;`**. Саму персональную UUID мы не публикуем. Наличие слова `Android` — свойство найденной строки, а не утверждение о платформе или универсальное правило для iOS.

Инструмент читает локальные plist из экспортированных Preferences, извлекает UUID/hex-кандидаты и проверяет их по известной исходной паре XML/hash. Регистр также проверяется. Ровно одно совпадение разрешает редактирование; ноль или несколько совпадений останавливают процесс. Не каждый iOS-экспорт обязан содержать нужное значение в таком виде.

Явное `--device-value` не отключает проверку. Если автоматический поиск ничего не нашёл, это не основание брать произвольный UUID, UDID телефона или значение из чужого примера.

## Нормализация и важное ограничение

В исходном исследовании игра хешировала представление `.NET XmlDocument.OuterXml`. Для двух XML из проверенного iOS-экспорта построчное `strip()` с последующей склейкой дало **в точности ту же строку**, что `OuterXml` при `PreserveWhitespace = false`. Сравнение было выполнено отдельно через .NET на Windows.

Это не универсальный XML-канонизатор. Например, `<Tag/>` и `<Tag />`, однострочные блоки, значимые пробелы внутри текста или другая сериализация могут дать различия. `ElementTree.tostring()` также не является заменой `OuterXml`.

Поэтому редактор сохраняет исходное текстовое представление и меняет только цифры в двух атрибутах. Он **не пересериализует** сохранение. Перед изменением та же нормализация должна воспроизвести оригинальный `.hash`. Если формат вашего XML отличается, работа останавливается вместо выдачи неподтверждённого результата.

Для независимого сравнения с .NET на своей локальной копии:

```powershell
$xml = [System.Xml.XmlDocument]::new()
$xml.PreserveWhitespace = $false
$xml.Load((Resolve-Path ".\users.xml").Path)
$normalized = (([IO.File]::ReadAllText((Resolve-Path ".\users.xml").Path) -split '\r?\n') | ForEach-Object { $_.Trim() }) -join ''
$xml.OuterXml -ceq $normalized
```

Ожидается `True`. Эта короткая PowerShell-проверка предназначена для обычного UTF-8 экспорта с CRLF/LF; производственный скрипт использует Python `splitlines()`.

## Основная и резервная пары

```text
users.xml             → свой рассчитанный users.xml.hash
users_backup.xml      → свой рассчитанный users_backup.xml.hash
```

В выходном архиве редактора оба XML одинаковы, поэтому одинаковы и их хеши. Это не разрешение копировать один `.hash` между произвольными различающимися XML.

## Что подтверждает проверка

Совпадение исходного хеша подтверждает воспроизведение расчёта для конкретных исходных данных. Совпадение нового хеша с собственной функцией — программная проверка согласованности. Отдельное подтверждение загрузки на iPhone необходимо: корректная контрольная сумма сама по себе не доказывает прохождение игровых и серверных ограничений.
